The main difference between PreToolUse and PostToolUse hooks is when they execute in the workflow.
PreToolUse hooks run before Claude Code uses a tool. They can inspect the request, validate inputs, enforce security policies, restrict access to sensitive resources, or block an operation if it violates project rules. Their primary purpose is prevention and validation before an action occurs.
PostToolUse hooks run after a tool has completed its work. They can analyze the results, trigger additional actions, format outputs, run tests, log activity, or verify that the operation completed successfully. Their primary purpose is processing and verification after an action occurs.
A practical PreToolUse example is validating file access. Before Claude Code reads or modifies a file, the hook can check whether the file is located in an approved directory and prevent access to sensitive files such as credentials or production configuration files.
A practical PostToolUse example is automatically running a code formatter and unit tests after Claude Code modifies source code. This ensures that any generated code follows project standards and does not introduce obvious errors before the changes are accepted.
In summary, PreToolUse hooks provide control and validation before tool execution, while PostToolUse hooks provide verification, automation, and follow-up actions after tool execution.
